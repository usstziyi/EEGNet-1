## FLOPs 与 MACs 的定义及关系

### FLOPs（Floating Point Operations）

**FLOPs = 浮点运算次数**，衡量模型执行了多少次浮点数计算。

一次浮点运算指的是对两个浮点数执行的**单次运算**：
- 1 次乘法 = 1 FLOP
- 1 次加法 = 1 FLOP
- 1 次除法 = 1 FLOP

---

### MACs（Multiply-Accumulate Operations）

**MACs = 乘加运算次数**，专门针对神经网络中最常见的计算模式。

神经网络的核心运算模式是点积（如卷积、全连接）：

```
y = w1*x1 + w2*x2 + w3*x3 + ... + wn*xn
```

每计算一项 `wi*xi`，需要：
1. **1 次乘法**：`wi * xi`
2. **1 次加法**：将乘积累加到 `sum` 上

这两步在硬件中通常被合并为一条指令——**乘加指令（MAC instruction）**。

所以：

```
1 MAC = 1 次乘法 + 1 次加法 = 2 FLOPs
```

---

### 为什么 FLOPs = MACs × 2

用一个具体例子说明：

**计算点积 `y = a*b + c*d`**

| 步骤 | 操作 | FLOPs |
|---|---|---|
| 1 | `temp1 = a * b` | 1 FLOP（乘法） |
| 2 | `sum = 0 + temp1` | 1 FLOP（加法） |
| 3 | `temp2 = c * d` | 1 FLOP（乘法） |
| 4 | `sum = sum + temp2` | 1 FLOP（加法） |
| **合计** | | **4 FLOPs** |

用 MAC 统计：
- 步骤 1+2 = 1 MAC（乘加）
- 步骤 3+4 = 1 MAC（乘加）
- **合计 = 2 MACs**

所以：**4 FLOPs = 2 MACs × 2**

---

### 卷积层的计算量估算

以你的 EEGNet 中第一个时间卷积为例：

```
Conv2d(1, 8, kernel=(1, 125))
```

**每个输出位置的计算**：
- 卷积核大小 = 125
- 每个位置需要 125 个 `乘加` 对
- 每个 `乘加` 对 = 1 MAC = 2 FLOPs

```
每个输出位置的 FLOPs = 125 × 2 = 250 FLOPs
```

**总输出位置**：
```
8 个输出通道 × 22 个空间位置 × 1000 个时间点 = 176,000
```

**总计算量**：
```
MACs = 176,000 × 125 = 22,000,000 (22 MMACs)
FLOPs = 22,000,000 × 2 = 44,000,000 (44 MFLOPs)
```

---

### 两种统计口径

在实际使用中存在**两种口径**：

| 口径 | 定义 | 适用场景 |
|---|---|---|
| **严格口径** | 1 MAC = 2 FLOPs | 硬件估算、学术论文 |
| **简化口径** | 1 MAC = 1 FLOP | 工程快速估算 |

**当前主流做法**：
- **torchinfo、thop 等库输出 MACs**，需要手动 × 2 转 FLOPs
- **很多论文直接使用 MACs**，不再换算为 FLOPs
- **有些论文直接写 "FLOPs"**，但实际统计的是 MACs（容易混淆）

---

### 总结

```
FLOPs  = 浮点运算总次数 = 所有乘、加、除等运算的总和
MACs   = 乘加运算次数  = 乘法+加法成对出现的次数

1 MAC = 1次乘法 + 1次加法 = 2 FLOPs

所以: FLOPs = MACs × 2
```

| 指标 | 单位 | 含义 |
|---|---|---|
| FLOPs | K/M/G/T | 浮点运算次数 |
| MACs | K/M/G/T | 乘加运算次数 |
| 换算 | — | FLOPs = MACs × 2 |

---

### 实际工程建议

在工程实践中，**MACs 已经足够衡量模型计算复杂度**，因为：
- MACs 直接反映硬件需要执行的指令数
- 避免了 FLOPs/MACs 的口径混淆
- 主流模型库（torchinfo、thop）都默认输出 MACs

**报告时建议明确标注使用的是 MACs 还是 FLOPs**，避免歧义。
